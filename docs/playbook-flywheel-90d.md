# 飞轮 + 90 天节奏

> 方法论总览（学习 → 项目 → 内容 → 课 → To C / To B）：[methodology.md](./methodology.md)

## 飞轮

```text
学习踩坑 ──► 开源 Infra（MeClaw 场景 A）
                │
                ├─► 自媒体 / 分析（信任）──► 知识付费
                │
                └─► 同仓封装 SaaS（场景 B：skills + hosted）
                        │
                        ├─► To C 订阅（验需求和定价）
                        └─► To B 私有化 / 席位（主收入）
```

## 分工原则

| 角色 | 负责 |
|------|------|
| **Infra（A）** | Star、信任、To B 合同 |
| **SaaS（B）** | 日活体感、To C 现金流、内容素材 |
| **知识付费** | 卖「可复制路径」 |
| **自媒体** | 卖「持续在场」 |
| **项目** | 卖「可交付资产」 |

三者必须指向同一楔子，不要 Infra 讲通用平台、SaaS 又去做客服大盘。

## 对外统一叙事

**IM Agent 基建 → 微信里能干活的助手。**（产品名 MeClaw）

## 90 天执行节奏

### 第 1–4 周｜只押场景 A

- [ ] 开源 MVP：扫码接入 + 多 Agent 路由（可安装、可演示）
- [ ] 产出 3 篇深度踩坑文（学习 = 内容素材）
  - 候选：《微信 Agent 接入对比》《ACP vs CLI》《私有化 Agent 网关的 5 个坑》
- [ ] 自媒体节奏立住：周更 1 踩坑 + 1 架构图

### 第 5–8 周｜同仓包场景 B 单技能

- [ ] 在 A 上包一层「单一技能」邀请制（如改 PR / 写周报 / 查报错）
- [ ] 公开成本账 + 结果演示（至少 3 条）
- [ ] 用量 / 额度墙（防滥用）

### 第 9–12 周｜课 + 试点收款

- [ ] 上架小册 / 录播（A：《从 0 搭微信 Agent 网关》或 B：《30 天做出可收费的微信 Agent》）
- [ ] 接 1～2 个付费私有化或小 B 席位试点
- [ ] 用试点案例再写 1～2 篇分析，反哺 Star 与询盘

## 决策备忘

- 只能先押一个 → **先押场景 A**
- 场景 B 用**同一仓库**加 `skills/` + `hosted/`，不另起炉灶
- 项目数量：Agent 线 **1 个 GitHub 仓库（meclaw）**
- 硬件互动线独立仓库；可后接「远程设备技能」当差异化 demo，不强绑
- **不要先做**云 SaaS 多租户 / 开放注册烧 Token
