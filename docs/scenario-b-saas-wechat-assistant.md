# 场景 B｜Agent SaaS：微信里的「工作助手」成品

**一句话：** 用户扫码即用，在微信里完成写代码、查日志、改文档、盯群消息——不暴露底层网关；用场景 A 的底座养产品。

**产品名：** MeClaw（hosted / skills）。**品类：** Agent SaaS。

**为什么适合个人：** 交付物是「会干活」，演示极强；个人订阅可验 PMF，再切小 B 席位。

## 各环节怎么落地

| 环节 | 怎么落地 |
|------|----------|
| **学习** | 提示词与技能包、长任务、人机确认、计费与滥用、合规（微信生态边界）；先做 1～2 个垂直技能做深 |
| **项目** | MVP：微信对话 → 固定技能（如「改 PR / 写周报 / 查报错」）；再加工作区、用量、邀请制；后期可挂「远程设备互动」当差异化 demo |
| **对外分析** | 《我不用打开 IDE，在微信里改完这个 Bug》《个人 Agent SaaS 的成本账》《为什么不做 App 做微信》 |
| **知识付费** | 《30 天做出可收费的微信 Agent》；技能包模板店（周报 / 客服话术 / 运维 Runbook） |
| **自媒体** | 人设：一个人把 Agent 做成能收钱的产品；偏结果演示 + 收入 / 成本透明 |
| **To C** | 个人订阅（按量 / 月卡）；邀请码冷启动；别一上来做开放注册烧 Token |
| **To B** | 小团队席位版：共享知识库、审计、管理员；或「帮你配置好技能包」的实施费 + 年费 |

## 变现顺序（建议）

邀请制 To C 验证付费 → 技能 / 课放大 → 小 B 席位。

底座继续反哺场景 A 的开源影响力。
