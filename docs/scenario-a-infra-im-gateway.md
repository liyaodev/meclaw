# 场景 A｜Agent Infra：中国 IM → Agent 接入与运行时

**一句话：** 做「把微信 / 飞书 / 企微接到任意 Agent」的开源底座 + 私有化运行时（会话、路由、权限、工具沙箱、可观测），而不是做通用 LangChain。

**产品名：** MeClaw。**品类：** Agent Infra。

**为什么适合个人：** 问题极窄、国内刚需；开源获客、私有化收费，不必先养用户 DAU。

## 各环节怎么落地

| 环节 | 怎么落地 |
|------|----------|
| **学习** | ACP / CLI 协议、会话与多租户、工具权限、沙箱、Trace / Eval、国内模型路由；对照 openclaw / Cursor Agent / Claude ACP |
| **项目** | ① 开源核心：扫码接入 + 多 Agent 路由；② 企业能力：审计日志、白名单工具、按群 / 按人策略；③ 可选：飞书 / 企微适配器 |
| **对外分析** | 《微信 Agent 接入对比》《ACP vs CLI》《私有化 Agent 网关的 5 个坑》——用真实踩坑当证据 |
| **知识付费** | 《从 0 搭微信 Agent 网关》小册 / 录播；企业内训「把内部 Claude / Codex 接到 IM」 |
| **自媒体** | 人设：Agent 基建实战；周更 1 踩坑 + 1 架构图；GitHub Star / 安装量当信任背书 |
| **To B** | 私有化部署、按节点 / 年订阅、二次开发；客户：小团队研发效能、内部运维 Bot |
| **To C** | 几乎不做 C 端订阅；最多「个人自托管一键包」引流到开源与课 |

## 变现顺序（建议）

开源 → 内容 → 课 / 咨询 → 私有化 To B。

不要先做云 SaaS 多租户。
