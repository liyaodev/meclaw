# 做事方法论：窄楔子起步 + 自建 claw 铺满

个人开发者阶段，**获客用窄楔子**（IM → Agent），**产品目标是沿「自建 claw」路径铺满完整 Agent Infra**，再用同一底座做一层 **Agent SaaS 业务练习项目（场景 B）**。

纪律：**不做无关赛道**；**产品场景不要无限加号**——价值链上的 To B / To C / 课 / 自媒体是**做事环节**，不是再开场景 C/D/E。侧业 KPI / 报价 / 名单等收款闭环放在私有仓 **earnclaw**（与 meclaw 并列），不要写进本开源仓。

## 两层不要混

| 层 | 是什么 | 有几个 |
|----|--------|--------|
| **产品场景** | 仓库里要交付的项目切片 | **只有 2 个：A（Infra）+ B（SaaS）** |
| **方法论环节** | 学习 → 项目 → 内容 → 课 → To B / To C 的飞轮 | 多环节，挂在 A 或 B 上变现，**不单独成「场景」** |

| 产品场景 | 卖什么 | 卖给谁 | 你为何要做 |
|----------|--------|--------|------------|
| **A｜Infra（A1–A6）** | 能力（自建 claw / 私有化运行时） | 开发者、企业 IT | 开源获客 + To B 主收入底座 |
| **B｜SaaS** | 结果（微信里会干活的助手） | 最终用户 → 小 B | **为搞懂 Agent SaaS 业务**而设的落地项目（见 [scenario-b](./scenario-b-saas-wechat-assistant.md)） |

内容、课、项目**共用同一套叙事**：

> **如何跑通自建 MeClaw → 微信里能干活的助手。**

编码顺序：**先 A1→A6（Infra 主干）→ 再做场景 B**。主路径见 [self-hosted-claw.md](./self-hosted-claw.md)。

### 为何「场景 A」有时看起来像 SaaS？

A 的**第一英里是 IM 接入**，演示形态是对话，容易被看成 C 端产品。判定标准：

| | Infra（A） | SaaS（B） |
|--|------------|-----------|
| 用户 | 自托管 / 二次开发的人 | 扫码即用的最终用户 |
| 暴露面 | 配置、网关、策略、部署 | 聊天结果；不暴露网关 |
| 收费 | 开源 + 私有化 / 实施（To B） | 邀请制订阅 → 小 B 席位（To C→B） |

A 里出现 skills 钩子、飞书机器人，仍是 **Infra 能力**；真正「卖结果、验 SaaS 生意」的项目是 **B**。

## 整条链（每个环节干什么）

学习、项目、对外分析、知识付费、自媒体、To B、To C **不是并列产品线**，是同一楔子上的闭环。任一环节产出，都要能喂给下一环。

```text
        ┌─────────────── 信任与获客 ───────────────┐
        ▼                                           │
   学习踩坑 ──► 项目（可交付资产）──► 对外分析 ──► 自媒体
        │              │                  │           │
        │              │                  └─────► 知识付费
        │              │
        │              ├─► 场景 A：开源 Infra / 私有化（To B）
        │              └─► 场景 B：SaaS 成品（To C → 小 B）
        │
        └────────────── 素材一律来自真实踩坑与交付 ──┘
```

| 环节 | 卖 / 产出什么 | 主要挂在 | 纪律 |
|------|---------------|----------|------|
| **学习** | 踩坑、可复述结论 | A 与 B 各自课题 | 学习 ≠ 囤课；要变成内容素材 |
| **项目** | 可安装 / 可演示资产 | A=meclaw 核心；B=`skills/`+`hosted/` | **只养 1 个 Agent 仓** |
| **对外分析** | 深度文 / 视频 | 两边共用叙事 | 证据来自自己的项目 |
| **自媒体** | 持续在场 | Infra 人设为主；B 贡献「能收钱的演示」 | 人设不周周换赛道 |
| **知识付费** | 可复制路径 | 「自建 claw」+「微信里做出可收费 Agent」 | 卖路径，不卖空概念 |
| **To C** | 邀请制订阅 | **主要是 B** | 不开放注册烧 Token |
| **To B** | 私有化 / 席位 / 实施 | **主收入偏 A**；B 可切小 B 席位 | 客户要窄，不做客服大盘 |

### 三者必须同楔

| 载体 | 卖点 | 禁止跑偏 |
|------|------|----------|
| 知识付费 | 可复制「自建 claw / 微信助手」路径 | 讲成通用 Agent 平台课 |
| 自媒体 | 持续在场 | 人设周周换赛道 |
| 项目 | 可交付资产 | A 讲 LangChain 竞品；B 去做全行业客服 |

## 场景怎么叠（不要再加场景号）

- [自建 claw 主路径](./self-hosted-claw.md) — A1–A6  
- [能力矩阵](./infra-capability-map.md)  
- [A1｜Channel Gateway](./scenario-a-infra-im-gateway.md)  
- [B｜微信工作助手（SaaS 业务练习项目）](./scenario-b-saas-wechat-assistant.md)  
- [概念：Infra + SaaS](./concepts-agent-infra-saas.md)  
- [开发上下文](./dev-context.md)

**不要**为 To B / To C / 课 / 硬件各开一个「场景 C/D/E」。它们进方法论环节表，或进 B/A 的交付清单。

**变现顺序（不要颠倒）：**

1. **A：** 开源 → 内容 → 课/咨询 → 用户自有云私有化 To B  
2. **B：** 邀请制 To C 验付费与 SaaS 手感 → 技能/课放大 → 小 B 席位（反哺 A 的 Star / 信任）

## 飞轮怎么转

```text
学习踩坑 ──► 开源自建 claw（场景 A）
                │
                ├─► 自媒体 / 分析（信任）──► 知识付费
                │
                └─► 同仓做 SaaS 练习项目（场景 B）
                        │
                        ├─► To C 订阅（验需求、定价、成本账）
                        └─► 小 B 席位；大 To B 仍以 A 私有化为主
```

执行节奏见 [飞轮与 90 天节奏](./playbook-flywheel-90d.md)。

## 每周自检

1. 本周产出是否仍落在「自建 claw / 微信里干活」？  
2. 学习是否变成了可公开的踩坑素材？  
3. 是否在加「场景 C」之类——若是，改挂到 A/B 或方法论环节？  
4. 对外一篇内容，能否服务 Star / 课 / 询盘中至少一环？  
5. To C 是否仍在邀请制？  
6. 是否在做自营公有多租户云？
