# 做事方法论：窄楔子 + 内容飞轮

个人开发者阶段，**不做通用平台**，押「窄楔子 + 内容飞轮」。

结合已有能力（WeClaw 微信↔Agent、远程互动硬件），两套场景刻意做成**同一技术底座的上下层**：

| | 卖什么 | 卖给谁 |
|--|--------|--------|
| **场景 A｜Infra** | 能力（接入 / 运行时 / 私有化） | 开发者、企业 IT |
| **场景 B｜SaaS** | 结果（微信里会干活的助手） | 最终用户 → 再切小 B |

内容、课、项目**共用同一套叙事**，全部指向同一楔子。

> 统一叙事：**IM Agent 基建 → 微信里能干活的助手。**（产品名 MeClaw）

若只能先押一个：**先押场景 A**——已有 WeClaw 基础，个人更扛得住「开源 + 私有化」；场景 B 同仓加托管/邀请版即可，不必另起炉灶。

---

## 整条链（每个环节干什么）

学习、项目、对外分析、知识付费、自媒体、To B、To C **不是并列清单**，是同一楔子上的闭环。任一环节产出，都要能喂给下一环。

```text
        ┌─────────────── 信任与获客 ───────────────┐
        ▼                                           │
   学习踩坑 ──► 项目（可交付资产）──► 对外分析 ──► 自媒体
        │              │                  │           │
        │              │                  └─────► 知识付费
        │              │
        │              ├─► 场景 A 开源 / 私有化（To B）
        │              └─► 场景 B 成品助手（To C → 小 B）
        │
        └────────────── 素材一律来自真实踩坑与交付 ──┘
```

| 环节 | 卖 / 产出什么 | 在飞轮里的职责 | 纪律 |
|------|---------------|----------------|------|
| **学习** | 踩坑、对照、可复述的结论 | 给内容与架构图供料；学习 ≠ 囤课 | 只学当前楔子：IM↔Agent、会话/权限/沙箱、技能与计费 |
| **项目** | 可安装、可演示、可报价的资产 | 开源 Star + To B 交付物 + SaaS MVP | Agent 线只养 **1 个仓（meclaw）**；硬件仓可后接，不强绑 |
| **对外分析** | 深度文/视频（对比、坑、成本账） | 把踩坑变成可检索的信任证据 | 标题对准搜索意图；证据来自自己的项目，不抄综述 |
| **自媒体** | 持续在场（周更节奏） | 把分析拆薄、拉长触达；人设稳定 | Infra 人设偏基建实战；SaaS 人设偏「能收钱的演示」——叙事仍统一 |
| **知识付费** | 可复制路径（小册/录播/内训） | 把「你会」变成「别人能照做」；现金流与名单 | 卖路径，不卖空概念；案例挂回 MeClaw |
| **To C** | 个人订阅 / 邀请制用量 | 验需求与定价；提供日活体感与演示素材 | 邀请制冷启动；不做开放注册烧 Token；Infra 侧几乎不做 C 端 |
| **To B** | 私有化 / 席位 / 实施 | **主收入**；合同与案例再反哺内容 | 客户要窄：研发效能、内部运维 Bot、技能包实施——不做客服大盘 |

### 三者必须同楔

| 载体 | 卖点 | 禁止跑偏 |
|------|------|----------|
| 知识付费 | 可复制路径 | 讲成通用 Agent 平台课 |
| 自媒体 | 持续在场 | 人设周周换赛道 |
| 项目 | 可交付资产 | Infra 讲 LangChain 竞品、SaaS 去做全行业客服 |

## 两套场景怎么叠

详见：

- [场景 A｜IM → Agent 网关](./scenario-a-infra-im-gateway.md) — 各环节落地表 + 变现顺序
- [场景 B｜微信工作助手](./scenario-b-saas-wechat-assistant.md) — 各环节落地表 + 变现顺序
- [概念：Infra + SaaS](./concepts-agent-infra-saas.md)

**变现顺序（不要颠倒）：**

1. **A：** 开源 → 内容 → 课/咨询 → 私有化 To B（不要先做云多租户）
2. **B：** 邀请制 To C 验付费 → 技能/课放大 → 小 B 席位（底座继续喂 A 的开源影响力）

## 飞轮怎么转

```text
学习踩坑 ──► 开源 Infra（场景 A）
                │
                ├─► 自媒体 / 分析（信任）──► 知识付费
                │
                └─► 同仓封装 SaaS（场景 B）
                        │
                        ├─► To C 订阅（验需求和定价）
                        └─► To B 私有化 / 席位（主收入）
```

分工：Infra 负责 Star、信任、To B 合同；SaaS 负责日活体感、To C 现金流、内容素材。

执行节奏与勾选清单见 [飞轮与 90 天节奏](./playbook-flywheel-90d.md)。

## 每周自检（方法论是否跑偏）

1. 本周产出是否仍落在「IM ↔ Agent / 微信里干活」？
2. 学习是否变成了可公开的踩坑素材？
3. 代码是否仍在 `meclaw` 单仓，而不是又开了一个「通用平台」？
4. 对外一篇内容，能否同时服务 Star / 课 / 私有化询盘中的至少一环？
5. To C 是否仍在邀请制，没有提前烧 Token？
